Stop Composer's own error wrappers and Temporal payloads from repeating a wrapped error's message.

The previous change closed the sinks Composer wrote to on the Node side. Three paths stayed open because each needed a decision: the async path's workflow-side logging, the workflow bag in `ApplicationFailure.details`, and `WorkflowStepError` inlining the original's message. All three are closed here, plus a fourth found while sweeping: FanOut inlined every failed child's message into the error it throws.

- **A wrapper's message is its own.** `WorkflowStepError`, `WorkflowBatchError` and `WorkflowErrorHandlerFailure` now carry only Composer's context -- which workflow, which step, which batch -- and never the wrapped error's message. **This changes every wrapper error message a consumer sees.** The original is on `.cause` and `.originalError`; `matchesError()` is unaffected. This also removes a trap: a wrapper copies the original's `code` but not `severity`, `table` or `constraint`, so a scrubber that rebuilds a database error's message from structured fields saw a wrapper that looked like the original and passed its inlined SQL through. `toLogContext()` likewise hands over the `Error` itself rather than a `{ name, message, stack }` projection.
- **Nothing Composer hands Temporal carries an error message.** A step failure travels as `{ stepName, code, parentCodes, type, cause }` at every depth -- **`StepFailureInfo.message` and `SerializedErrorInfo.message` are gone**, from the error-handler activity's argument and from the `ApplicationFailure` details alike, both of which persist in event history. A crashed error handler and a failed FanOut child are likewise named by code, not by message.
- **The bag is its own details entry.** An unhandled workflow error now throws with `details: [{ error }, { bag }]` instead of `[{ bag, error }]`, so a scrubbing failure converter can drop the bag whole without rebuilding the error beside it. **Read partial workflow state from `details[1].bag`.** Composer's own client reads the new layout and falls back to the old one, so a workflow started by an older bundle still yields its bag.
- **A code recovered from a `CODE: message` prefix must look like a code.** The prefix is now required to match `[A-Z0-9_]{2,50}`. A bare 50-character cutoff laundered arbitrary message text into `code` -- `constraint "u_email": Key (email)=(jane@x.com)` yielded a 20-character prefix quoting the row -- and `code` is emitted precisely where the message is withheld.
- **`details[0].stack` carries frames only.** V8 opens a stack with its `name: message` header, so copying `error.stack` whole put a second copy of the message where a converter scrubbing `message` and `stackTrace` would not look.
- **`Runtime` is re-exported.** Workflow-side `wf.log` lines are routed by Temporal's own `Runtime` logger, not the injected `ComposerLogger`. Composer does not wire the two together: `Runtime.install` is process-global and single-shot, the per-worker alternative is a sink name Temporal reserves, and sink arguments cross the sandbox by `postMessage`, so an `Error` could not arrive intact for a serializer anyway. Composer stops putting raw text in those lines instead, and re-exports `Runtime` for a consumer who wants to route them.
